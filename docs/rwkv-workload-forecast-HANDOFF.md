# RWKV workload forecast graph

The Statistics graph delegates simulation to the Anki fork's `aqt.rwkv_scheduler` forecast API. It passes the active search, forecast horizon, and number of simulated futures; polls the background job; and can cancel it. A compatible, running RWKV backend is required.

The graph plots daily review due and done, introductions, lapses, or study time. It defaults to 7 days and 3 paths; users can choose longer horizons or more paths. For Instant on a compatible fork, three paths represent lower, central and higher aggregate answer outcomes, using the same sampled historical sessions and unmodified recall probabilities. The tooltip identifies the answer scenario and the shaded area spans the three paths. These workload paths can cross, and the area is an approximation, not a confidence interval. Older forks may return the legacy `R − σ`, `R`, and `R + σ` scenarios, or only ordinary sampled futures; for the latter, the graph shows a rough mean ± sample standard deviation clipped to the simulated range, recovered from type-7 p1, p50 and p99. With 20 or more futures, lines show the mean and median and bands show the 5th–95th and 1st–99th percentiles. Changing metrics redraws the SVG, including its axis.

For an Instant forecast, the fork samples real historical study timings and successful-answer patterns, predicts recall with the Instant model, and applies the configured review limits, new-card limit toggle, queue refresh settings, and learning steps. New three-path scenarios select approximate aggregate outcomes without applying the same offset to every simulated probability. The fork calibrates the spread against historical daily residuals relative to the answer randomness already modeled; when history is insufficient it falls back to the model's variability. Frequent full queue refreshes on a large search can take a long time. The forecast does not model skipped days, reviews outside the search, sibling burying, load balancing, or future settings changes. A search that includes RWKV-Curve scheduled cards is not supported by the Instant path. The complete algorithm and its limitations are documented in the fork's `docs/rwkv.MD` under “Workload Forecast”.

Newer fork builds report Instant results progressively per path and day. While the job runs, the graph draws the central days that are ready and adds each outer answer path and the spread when the corresponding values arrive; missing values are not interpolated. For stochastic forecasts it draws the provisional mean without percentile bands until the job completes. The progress count is in simulated path-days when this stream is available; old forks and Curve jobs retain path-level progress and a final graph. Cancelling leaves any displayed partial graph marked preliminary, and starting a new run clears the previous result.

The bridge is in `workload_forecast.py`, the data transformations are in `src/ts/workloadForecastData.ts`, and the graph and controls are in `src/ts/WorkloadForecastGraph.ts` and `src/ts/WorkloadForecast.svelte`. Verify the TypeScript tests and production build, package with `./package.sh`, and synchronize the verified package to the local add-on runtime. Testing the Instant path requires an Anki fork build that includes the corresponding backend implementation.
